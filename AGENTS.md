# Repository Guidelines

## Stack

- Next.js 16 App Router, React 19 with the React Compiler, TypeScript 6, Tailwind CSS v4 and shadcn/ui.
- PostgreSQL with Drizzle ORM, BetterAuth, and Zod 4 at every runtime boundary.
- React Hook Form, TanStack Query and Zustand on the client.
- Vercel AI SDK 7 with Groq, and an OpenRouter model for drafting application answers when configured; separate services for LaTeX PDF compilation and OCR; SeaweedFS over the S3 API for stored files.
- Node.js 24, pnpm, Vitest, Playwright, ESLint and Prettier.

## Module organization

- `src/app`: routes. Dashboard features keep their components, `queries/`, `mutations/` and `store/` together. API routes live in `src/app/api/<feature>/`: `route.ts` handles HTTP, services hold the logic, and `validators.ts` exports Zod schemas shared with the client.
- `src/components`: shared UI primitives built on shadcn/ui.
- `src/lib`: environment validation, database, auth, logger, resume templates and shared helpers.
- `services/`: the LaTeX compiler and the OCR service, each with its own image and README.
- `scripts/`: migration, worker and container entrypoints.
- `tests/`: PostgreSQL integration and Playwright suites. Unit tests sit next to their modules.
- `migrations/`: SQL generated by `pnpm run db:generate`. Commit it with the schema change that produced it.

## Before finishing a task

Run these and fix every error and warning before reporting a task as done:

```sh
pnpm run format
pnpm run lint
pnpm run typecheck
pnpm run test
```

## Guidelines

- Do not introduce `any`. Any necessary `eslint-disable` or `@ts-expect-error` must have a comment explaining why.
- Treat request bodies, JSON and model output as `unknown` until a Zod schema validates them.
- For UI work, follow the design system in `.claude/skills/design-system/SKILL.md`.
